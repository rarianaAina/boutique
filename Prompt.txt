# PROMPT — APPLICATION DE GESTION DE BOUTIQUE OFFLINE-FIRST

Tu es un développeur logiciel senior spécialisé en applications de gestion commerciales, POS, inventaire, bases de données locales, architecture offline-first et synchronisation multi-sites.

Je veux que tu développes une **application professionnelle complète de gestion de boutiques spécialisées dans la vente de smartphones, accessoires électroniques et matériel informatique**.

L'application doit être pensée comme un véritable logiciel commercial pouvant être utilisé quotidiennement par plusieurs boutiques et plusieurs utilisateurs.

---

# 1. OBJECTIF PRINCIPAL

L'application doit fonctionner **entièrement hors ligne par défaut**.

Chaque boutique possède sa propre base de données locale et doit pouvoir continuer à fonctionner normalement sans connexion Internet.

Internet ne doit être nécessaire que lorsqu'une opération nécessitant une communication entre plusieurs boutiques est demandée, notamment :

* transfert de produits d'une boutique vers une autre ;
* synchronisation de données explicitement demandée ;
* éventuellement synchronisation administrative selon les besoins futurs.

IMPORTANT :

Ne construis PAS une application qui dépend constamment d'une API distante.

Le fonctionnement principal doit être :

**Utilisateur → Application locale → Base de données locale**

et non :

**Utilisateur → Internet → API → Base de données**

L'application doit rester utilisable même avec une connexion Internet totalement absente.

Ne crée pas de fausses données uniquement pour faire croire que l'interface fonctionne.

Toutes les actions de l'interface doivent être connectées au véritable système de données.

---

# 36. QUALITÉ DU CODE

Le code doit être :

* TypeScript strict ;
* fortement typé ;
* modulaire ;
* maintenable ;
* documenté lorsque nécessaire ;
* sans duplication inutile ;
* sans fonctions gigantesques ;
* sans logique métier directement dispersée dans les composants UI.

Évite :

* any inutile ;
* TODO laissés partout ;
* mock permanent ;
* données hardcodées ;
* composants de plusieurs centaines de lignes lorsque cela peut être séparé ;
* logique métier dans les composants ;
* dépendances inutiles.

---

# 37. RÈGLE FONDAMENTALE

Le logiciel doit être conçu comme un **véritable logiciel commercial offline-first**, et non comme une simple interface de démonstration.

Les données de stock, IMEI, ventes, achats, remboursements, échanges et transferts doivent être cohérentes et traçables.

La priorité absolue est :

**Intégrité des données > simplicité du code > esthétique.**

Mais l'interface doit malgré tout avoir un niveau de finition professionnel.
